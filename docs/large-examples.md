# Large example graphs

Load these from **Load example**. Each graph is a separate static file, fetched
only when selected. The examples carry a layout, colors, and label settings; the
default **Settings → Embedding → On graph load** mode applies them when loaded.

| Example | Nodes | Edges | What to explore |
| --- | ---: | ---: | --- |
| World Airline Routes | 3,265 | 67,091 | Hubs, long-haul bridges, airline-specific subnetworks |
| Spiral Trade Routes | 21,840 | 87,156 | Six arms, relay hubs, and rare links between arms |
| New York City Streets (2024) | 117,104 | 154,808 | Street geometry, boroughs, paths, ramps, and major roads |
| US County Migration (2016–2020) | 3,221 | 254,348 | County migration hubs and within-state versus interstate flows |
| Debian Package Ecosystem | 76,940 | 487,602 | Runtime dependencies, build dependencies, and source-to-binary links |

Airlines and county migration retain geographic 2D maps and become globes in
3D. Alaska, Hawaii, and Puerto Rico are insets in the county graph's 2D map;
switching back from 3D restores that map. New York streets keep their real 2D
geometry and use *stylized* height in 3D because the source has no elevation.
The synthetic spiral keeps its six-arm plan in 2D and separates the arms by
height in 3D. The package graph groups packages by broad Debian section, with
separate areas for language ecosystems, documentation, and games. Its groups
also start at different depths, with GPU force enabled and no hidden warmup.

## Try these searches and filters

- **Flights:** Search `code:AMS`, `city:Tokyo`, or `country:Japan`. In
  **Settings → Filters**, the edge expression `airline === "KL"` isolates an
  airline. Route edges include `distance_km` and `stops`.
- **Spiral:** Search `arm:Indigo`, `sector:7`, or `role:relay`. The edge filter
  `type === "cross-arm"` reveals the sparse inter-arm bridges. Shortest paths
  between different arms show why these bridges and the core matter.
- **Streets:** Search `street:Broadway`, `borough:Queens`, or `role:junction`.
  Filter edges with `type === "highway"` or `type === "path"` to isolate a
  road class. Each edge has a `length_m` value.
- **Migration:** Search `county:"Maricopa County"`, `state:CA`, or
  `fips:06037`. The edge expression `movers_estimate >= 250` isolates larger
  estimates; `type === "between-states"` shows interstate flows. Each edge
  carries the published 90% margin of error as `moe_90`.
- **Packages:** Search `label:python3`, `section:science`, or
  `summary:database`. The edge expression `type !== "build-depends"` hides
  build-time requirements. Try **Analytics → Degree centrality** to inspect
  heavily depended-on packages.

## Sources and interpretation

- **World Airline Routes** is derived from the [OpenFlights airport and route
  database](https://github.com/jpatokal/openflights/tree/7d1a611e070295dba776d6afb86e57d0d1aa1cef/data).
  Database © OpenFlights contributors, under [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/);
  individual contents are under [DbCL 1.0](https://opendatacommons.org/licenses/dbcl/1-0/).
  This example is a derived database under ODbL 1.0. It is a snapshot of the
  route database, not a live flight schedule. Unresolved airports, self-routes,
  and exact duplicate route records were omitted. Each airline's route remains
  a separate edge.
- **US County Migration** comes from the [U.S. Census Bureau's 2016–2020 ACS
  county-to-county flow file](https://www.census.gov/data/tables/2020/demo/geographic-mobility/county-to-county-migration-2016-2020.html)
  and [2020 county Gazetteer](https://www.census.gov/geographies/reference-files/2020/geo/gazetter-file.html).
  Edges run from residence one year ago to current residence. Values are
  survey-based estimates of annual movers over the five-year period, with a
  90% margin of error; they are not exact mover counts. The example keeps
  positive flows whose endpoints match 2020 U.S. county geographies. The node
  field `population_1y_plus` is the ACS estimate for people aged one year or
  over in the current county.
- **New York City Streets** is derived from the [2024 Census TIGER/Line All
  Lines shapefiles](https://www.census.gov/programs-surveys/geography/technical-documentation/complete-technical-documentation/tiger-geo-line.2024.html)
  for the Bronx, Brooklyn, Manhattan, Queens, and Staten Island. Road edges
  use Census topology node IDs to join streets at real junctions; curve
  vertices are kept as nodes so a street's shape remains legible when zoomed
  in. The largest connected component contains over 99% of its nodes. The 3D
  height is a visual relief generated by this example; it is not surveyed
  elevation. The graph does not model turn restrictions or travel times and is
  not suitable for navigation.
- **Spiral Trade Routes** is a deterministic synthetic network. The arms,
  relay hubs, and sparse bridges are designed to make community structure and
  path bottlenecks visible. It does not represent real places or trade flows.
- **Debian Package Ecosystem** uses the [Debian 12 (bookworm) `main` amd64
  Packages and Sources indices](https://deb.debian.org/debian/dists/bookworm/main/).
  Nodes combine source and binary packages with the same name. Edges represent
  `Depends`, `Pre-Depends`, main `Build-Depends`, and source `Binary` outputs.
  For a dependency with alternatives, the first target present in the amd64
  index is shown. Virtual and unresolved dependencies, `Recommends`, and
  `Suggests` are omitted; version constraints and architecture guards are not
  evaluated. This is an exploration graph, not an APT dependency solver.
  Package descriptions and relationships come from Debian archive metadata;
  package software has its own licensing.

## Rebuild

Run `python scripts/generate-large-examples.py` from the repository root.
The generator uses only Python's standard library, verifies pinned SHA-256
hashes, caches raw downloads in `.tmp/example-sources/`, and writes the five
compact JSON files to `data/`. Use `--only airlines`, `--only spiral`,
`--only nyc`, `--only migration`, or `--only debian` to rebuild one example.

Large examples use `edgeEncoding: "indexed-v1"`: an edge tuple contains source
and target node-array indices, an index into `edgeTypes`, then values for
`edgeProperties`. The importer expands this to ordinary graph edges, so search,
filters, analytics, and export use the same graph model as smaller examples.
